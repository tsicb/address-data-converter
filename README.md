# address-data-converter

CSV / Excel の住所関連情報を相互補完・正規化・検証する GitHub Pages アプリです。

## 主な用途

手元にある住所データから、郵便番号、住所分解、自治体コードなど複数の表現を生成し、
ExcelやGoogleスプレッドシート等で再利用しやすい形に整えます。

## 入力

- CSV
  - UTF-8 / Shift_JIS を自動判定
- XLSX
  - `住所変換結果` シートがあれば最優先
  - なければ一番左の表示シートを初期選択
  - 複数シート時は画面上で切り替え可能

入力ファイルにすべての対象列が存在する必要はありません。

## 出力列

- 仕事番号
- 仕事名
- 郵便番号（ハイフン）
- 郵便番号1
- 町域未指定郵便番号（ハイフン）
- 町域未指定郵便番号1
- 全住所
- 都道府県
- 市区町村
- 町域
- 町域以降
- 詳細住所あり
- 県コード1
- 市区町村コード1
- PrefCityコード
- 標準地域コード
- 補完判定
- 補完項目
- 確認メモ

### コード仕様

例: 北海道札幌市中央区

- 県コード1: `1`
- 市区町村コード1: `101`
- PrefCityコード: `1101`
- 標準地域コード: `01101`

`標準地域コード` は5桁固定、`PrefCityコード` は先頭0なしです。

### 住所列の仕様

- `町域`: 郵便番号マスタで特定できる町域
- `町域以降`: 市区町村より後ろの住所。番地等がなく町域までしか確定できない場合も、町域を出力します
- `全住所`: 町域まで確定した場合は、番地等がなくても `都道府県 + 市区町村 + 町域` まで出力します
- `詳細住所あり`: `1` = 町域より後ろに番地等あり、`0` = 町域まで、空欄 = 町域未確定

`詳細住所あり` は派生判定列のため、Excelを再投入した場合も現在の住所情報から再計算します。

## 判定方針

入力済みの値は原則として自動上書きしません。
郵便番号、住所、自治体コードを独立して照合し、確定できる空欄だけを補完します。

判定ステータス:

- `OK`
- `補完あり`
- `要確認（候補複数）`
- `要確認（不一致）`
- `判定不可`

前回の `補完判定` / `補完項目` / `確認メモ` は再投入時に再計算します。

## Excel出力

メイン出力は XLSX です。

- `住所変換結果`: 全行
- `要確認`: 要確認・判定不可の行
- 郵便番号・各種コードは文字列形式
- 今回補完したセルを色分け
- フィルター・先頭行固定
- 元ファイル名 + 日時を含むファイル名で出力

CSV出力は補助機能として残しています。

## 選択列コピー

処理結果から必要な列だけを選び、TSV形式でクリップボードへコピーできます。
ExcelやGoogleスプレッドシートへそのまま貼り付けられます。

## 共通マスタ

住所マスタは別リポジトリの GitHub Pages を参照します。

- `/address-master/zipcode_master.json`
- `/address-master/municipality_master.json`

処理開始前にブラウザへ先読みし、ファイル投入後の判定処理では外部API通信を行いません。

## 構成

- `index.html`: UI、CSV / XLSX 入出力
- `address-core.js`: 住所判定・補完ロジック
- `tests/run-tests.js`: 代表ケースの自動テスト
- `.github/workflows/address-tests.yml`: GitHub Actions 自動テスト

## 自動テスト

現在、次のような代表ケースを自動確認しています。

- 全住所のみ
- 郵便番号のみ
- 都道府県 + 市区町村
- 標準地域コード
- PrefCityコード
- 県コード + 市区町村コード
- 市区町村名の全国一意 / 重複
- 郵便番号と住所の一致 / 不一致
- 複数町域・複数自治体にまたがる郵便番号
- 全角郵便番号・全角コード
- Excel再投入を想定した診断列再計算
- マスタに存在しない郵便番号・住所

`main` への関連ファイルのpush時に GitHub Actions で実行されます。
